# 编辑器实时渲染优化方案

## 根因结论

「延迟后跳闪」来自 [SegmentEditorRow.vue](frontend/src/components/SegmentEditorRow.vue) 的渲染机制：编辑器是**手写 contenteditable**，高亮(术语/搜索/QA)、可见空白字符、修订痕迹 diff 与用户真实编辑的文本共用同一棵 DOM 树。每次输入触发 `editorHtmlContent` 重算 → `watch` → 150ms 防抖(`REVISION_RERENDER_DEBOUNCE_MS`) → `syncEditorHtmlFromState` 执行 `editor.innerHTML = nextHtml` **整段销毁重建** → `restoreSerializableCaretPosition` 重定位光标。

- 延迟 = 150ms 防抖 + store 往返(`scheduleSync`)
- 跳闪 = 整段 `innerHTML` 重写引发的重排重绘 + 光标重置
- 批量删除 = 每个受影响行各自触发一次整段重写，叠加虚拟列表固定行高回流

关键瓶颈代码：`editorHtmlContent`(L412)、`watch(editorHtmlContent)`(L1808)、`scheduleRevisionRerender`(L1697)、`syncEditorHtmlFromState`(L1712)。

---

## 方案对比

- **方案 A — 低风险微调(保留 contenteditable)**
  - 思路：纯文本输入时不再整段重写 DOM；仅当装饰内容(修订/高亮/可见字符)真正变化时才重绘，且改用增量 patch。
  - 优点：改动集中在 1 个文件、风险低、1-2 天可见效，能消除"无修订纯输入"场景的全部跳闪。
  - 局限：修订痕迹聚焦编辑时仍需局部重绘 diff，无法 100% 根除该场景的轻微跳动。

- **方案 B — 编辑层/渲染层分离(overlay)**
  - 思路：contenteditable 只承载纯文本与光标；高亮、修订痕迹、可见字符放到一个与文本逐字符对齐的绝对定位渲染层(或 CSS Custom Highlight API)。输入只更新渲染层，编辑层 DOM 永不重建。
  - 优点：彻底无跳闪、不丢光标，修订痕迹也不再抖动。这是 CodeMirror/Monaco 的经典做法。
  - 局限：渲染层与文本的像素对齐(换行、富文本 b/i/u、sub/sup)实现复杂，中等工作量。

- **方案 C — 引入成熟编辑器内核(ProseMirror/TipTap 或 CodeMirror 6)**
  - 思路：用内核的 decorations/marks 机制承载高亮与修订痕迹，事务化更新；修订痕迹用 prosemirror-changeset / track-changes 插件。
  - 优点：最完善，根除跳闪/光标/IME/undo/批量一系列问题。
  - 局限：需重写 SegmentEditorRow 约 2000 行手写逻辑(序列化、撤销栈、IME、修订 diff、富文本清洗)，迁移与回归成本最高。

## 推荐路线：先做 A，按需上 B，C 作为远期储备

### 阶段一(必做)：方案 A 微调
核心是让"纯文本输入"不再触发整段 `innerHTML` 重写。

1. 新增 `hasAnyDecorations()` 判定：`pendingRevision || hasTargetHighlights() || showVisibleChars`。
2. 改造 `syncEditorHtmlFromState`：当聚焦且 `!hasAnyDecorations()` 且 `serializeEditorContent(editor) === getTargetStateText()` 时直接 `return`，不重写(用户输入的 DOM 已正确)。当前的 `editor.innerHTML === nextHtml` 比较因 `\n`/`<br>`、文本节点包裹差异几乎总不相等，需改为按序列化文本比较。
3. 改造 `watch(editorHtmlContent)` / `scheduleRevisionRerender`：区分"纯文本变化"与"装饰变化"，纯文本变化不进入重绘分支。
4. 聚焦编辑期间挂起 term/search/QA 高亮(失焦后 `syncFocusedTargetHighlightsFromState` 恢复)，避免输入时 `editorHtmlContent` 随高亮重算——这是多数 CAT 工具的常见做法。
5. 修订痕迹聚焦编辑：将整段 `innerHTML` 重写替换为对 diff span 的增量 DOM patch(morphdom 思路)，只更新变化节点，保留光标所在节点。

### 阶段二(可选，彻底消除修订痕迹场景跳闪)：方案 B overlay
1. `SegmentEditorRow` 模板拆分为 `editor-input`(透明文本/纯文本 contenteditable)与 `editor-overlay`(绝对定位渲染层)。
2. 高亮与修订痕迹改为渲染层的 Vue 响应式模板(无需手动操作编辑层 DOM)；若确认可用现代浏览器，优先用 CSS Custom Highlight API 做高亮，连渲染层都省去。
3. 复用现有 `computeDiff`、高亮计算函数，仅改变"输出目标"(从写入 contenteditable 改为驱动渲染层)。

### 阶段三(远期储备)：方案 C 内核化
仅在未来需要协同编辑、复杂富文本或修订痕迹合并冲突处理时启动；用 CodeMirror 6 decorations 或 ProseMirror marks 重建编辑核心。

## 批量删除多选的专项优化(阶段一并行做)
在 [WorkbenchView.vue](frontend/src/views/WorkbenchView.vue) 批量清空/删除入口，批量期间设置标志位让受影响行跳过逐行防抖重绘，操作结束后统一 `nextTick` 刷新一次；并确认 `segmentStore.updateTarget` 批量调用合并到一次状态提交，减少虚拟列表多次回流。

## 风险与验证
- 重点回归：IME 中文输入(composition)、撤销/重做(`undoStack`)、富文本格式(b/i/u/s/sub/sup)、修订痕迹接受/拒绝、虚拟列表滚动定位(`focusIndex`)。
- 验证场景：快速连续输入、长句段输入、多选后批量删除、修订模式下编辑、术语/搜索高亮命中时编辑。
