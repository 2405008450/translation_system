# 双 Excel 位置对齐与校对导出

校对项目的“原文 + 译文两个文档”入口支持上传两个 XLSX 文件。复杂工程规格表无需先取消合并或删除图片，也不需要将原文和译文合并到一张表。

## 操作流程

1. 分别上传原文和译文 XLSX，选择两侧语言，解析并预览。
2. 预览显示工作表数量、位置配对数量、结构差异、缺口及图形文字覆盖数量。
3. 生成整格对齐草稿，进入现有工作台确认或调整对应关系。结构差异标为中置信，缺口单独保留，系统不把它们自动挪到相邻单元格。
4. 完成对齐后，沿用已有人工校对、LLM 校对和修订流程。
5. 导出 Excel 校对报告，或导出目标原格式 Excel。对齐阶段只提供对齐报告。

## 处理范围

- 单元格按工作表名称和坐标配对；工作表顺序改变不影响名称相同的配对。工作表改名或缺失时保留缺口，交由人工调整。
- 合并区域只提取左上角单元格。原文与译文合并范围不同的配对需要人工确认。
- 可编辑形状和文本框按工作表、对象标识和段落位置配对；位置或段落结构变化时标为待复核。
- 数字、布尔值、日期类型、公式及完整 SD_/RV_ 协议标签不送入文字校对。字符串形式的纯数字同样跳过，避免译文将数字改成字符串后产生虚假的增译。
- 包含隐藏工作表中的文字，并在上传预览提示。
- 图片内部文字未使用 OCR，预览和报告均提示人工检查。图片资源保留原样。

## 导出行为

- 独立报告列出两侧位置、原文和原译文；校对阶段增加校对译文、修改状态、确认状态和修改理由，并附覆盖说明。
- 新增导出格式 `proofreading_xlsx_target`。只在双 Excel 的校对阶段、译文缓存存在时开放。
- 原格式导出以保存的译文副本为底稿，不插列、不重建工作簿。只修改指定单元格或图形段落；其余 ZIP 部件保持原样。
- 共享字符串修改转成该单元格的独立富文本，避免影响其他引用同一共享字符串的单元格；保留单元格和文字 run 的样式。
- 对齐阶段的人工译文修订也会进入回写结果。修改后的跨单元格配对、没有明确目标位置的补译无法直接回写；需要先拆分或调整配对，也可以完整导出独立报告。
- 既有 DOCX/DOC/TXT/HTML 双文档链路和同表列映射模式保持兼容。复杂表格的列映射提示引导用户改用双 Excel 对齐。
- 无数据库字段变更，无需执行数据库迁移。部署需同时更新后端与前端，并重启后端工作进程。

## 验证记录

- 用户提供的原文和译文均有 16 个工作表、1,554 个合并区域、237 个公式单元格及 13 个图片对象。
- 排除纯数字与受保护标签后，两侧均提取 23,135 个文字单元格和 75 段图形文字，得到 23,210 对配对，零缺口，2 处图形位置或结构差异待复核。
- 在临时 SQLite 和临时文件目录中完成真实文件的批次创建、对齐落库、工作台物化、校对报告和原格式回写。未修改客户文件，也未调用 LLM。
- 修改一个单元格和一个图形段落后，只有对应的工作表 XML 和绘图 XML 发生改变。重新解析确认新增后缀完整，公式数量、合并数量和图形文字数量不变。
- 回归覆盖整格换行、数字类型变化、合并差异、工作表重排、增译/缺译、富文本回写、共享字符串隔离、公式文本保护、报告理由、对齐阶段人工修订和跨单元格回写限制。
- 现有导出队列测试有 5 项基线失败，已使用 HEAD 中的原版模块复跑，失败项和原因一致；新格式的导出分发另有集成测试覆盖。
