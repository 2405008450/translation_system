# Word 导出自动句序与文本块位置检查

## 基本信息

- 日期：2026-10-19。
- 状态：已修复、回归并发布；应用及 5 个后台服务均已更新，发布后验收通过。
- 需求：每次导出自动检查真实输出的句段先后位置，防止内容全部存在但顺序错误。
- 范围：中央 Word 导出器的单语和两种保留布局双语输出，以及复用该导出器的入口。默认执行，无需另行开启。
- 不修改源文件、译文、断句规则或数据库结构；检查失败时停止生成结果。

## 原因与最小复现

前次增加的消费凭据证明每段处理了一次，但不能证明实际 XML 中的文字位置。单独存在于诊断脚本的顺序验证也不能保护后续日常导出。

脱敏复现：一个 Word run 含三个句段，第三段译文带换行；恢复旧的“在整个 run 前插入换行译文”逻辑。所有目标文字都存在、消费次数均为 1，但成品顺序变为第三句、第一句、第二句。正式检查必须拒绝返回该文件。

## 正式检查

1. 写入前记录句段的预期顺序和对应 XML 输出范围。双语内联副本共享消费凭据，但核验其实际的源文/译文组合。
2. 在中央导出器序列化前、富文本/换行/修订标记展开和内部格式清理之后，读取最终可见内容，逐段向前匹配；重复译文必须找到各自独立的后续出现位置。
3. 完整覆盖的文本块额外核对整块内容与预期拼接结果相等，阻止多余复制或利用其他句子中的相同子串通过检查。部分覆盖范围保留原文之外的内容，仍按预期逐一检查顺序。
4. 按最终文档树的实际位置检查段落、单元格及整张表与相邻段落的相对顺序；被移除、已脱离文档的输出范围也拒绝通过。
5. 页眉页脚、正文、脚注尾注、批注按实际 XML part 定位；同一 notes/comments part 的多个 story 均纳入检查。文本框有独立阅读范围，嵌套表格按所属表核验，不强行与外层跨段线性比较。
6. 真实修订仅读取接受后的可见结果，删除侧文字不能满足匹配。复选符号和宏字段读取实际可见内容；公式位置使用原 XML 节点身份核验，不跳过含公式的句段。
7. 图表按各标签节点核验文字，标签在 XML 中的物理排列不当作正文阅读顺序。双语纯数字/公式单元格沿用现有“只保留一次”策略，显式登记此项豁免。

空译文保留源文、显式空白目标、整句删除修订、表格译文逐行分配等路径分别登记正确预期，不把有意留空当作遗漏。普通自动编号前缀沿用现有导出规则。

检查属于文字次序及结构定位校验，忽略普通空白差异，不替代字体、分页、视觉排版或翻译语义验收。

## 失败策略

- 顺序或位置无法核实、完整文本块与预期不一致、文本块移动或定位范围失效时抛出明确的 `ValueError`。
- 异常含句段标识，不包含客户正文或完整译文。既有导出队列会将新任务置为失败，不将残缺/错位结果标记为成功。
- 原有未消费/重复消费、内部标记残留检查继续执行，顺序检查不能被消费计数替代。
- 不自动放宽检查、不静默返回旧导出或错误文件；已下载文件保持原样，新任务使用新检查。
