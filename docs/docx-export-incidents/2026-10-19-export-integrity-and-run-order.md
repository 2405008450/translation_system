- 图二所指内容对应第 94 段。此次初检只排除了跨原文块移动，对普通文本换行造成的块内错位验收不足。后续直接读取云上实际导出任务文件，已复现 93→97→94→95→96 的错误顺序并完成修复，详见[真实文件位置复核与换行修复记录](2026-10-19-multiline-target-position.md)。本记录的早期块归属检查不能替代该位置验证。
- 独立脱敏回归确实复现另一种错位：同一个 `w:r` 内有多个 `w:t`、分页或换行节点，连续富文本句段会被插到整 run 的错误位置。
- 分页漏句最小例：短标题、`w:lastRenderedPageBreak`、足够长的正文及末句处于同一段落。工作区按显示换行拆出三个句段，旧导出忽略分页标记，只取得两个句界，漏掉末句。
- 不同分页位置并不一定拆出独立句段；回归同时覆盖页中半句保持原解析合并规则的情况，不改变既有任务断句。

## 根因

1. 工作区把自动分页标记转为 `PAGE_BREAK_FRAGMENT`；旧导出器忽略该节点。其显示换行可能参与标题等断句规则，使两端的句界数量不一致。
2. 旧导出按重新识别的句界逐个消费译文，末尾仍有译文时也返回成功；没有块级和全文件消费检查。
3. 富文本替换根据当前 `w:t` 内的起点决定是否直接插到 run 前面，遗漏了同一 run 内更早文本节点的存在。
4. 格式和修订标记展开只处理所在文本节点的前后字符串，未同步拆出 run 中后续文本、分页及其他节点，导致内容次序可能改变。

## 修复方案与失败策略

- 解析、导出共用分页片段的显示及源文语义。`legacy` 保留自动分页边界信息；`en_docx_v1` 继续忽略自动分页标记。显式分页保留结构，不写入标记节点的文本值。
- 源文完整相符时，按已保存句段原文和字符位置直接定位，不依赖本次重新断句结果。未匹配到完整范围时保留原有拆分、合并兼容路径。
- 富文本全部按字符偏移排队，在当前 XML 树中定位后展开；格式和修订展开均在真实文本节点处拆 run，把后续文字、分页、图片及样式移至后半 run。
- 每个导出句段携带独立消费凭据，内联双语副本共享凭据；块内遗漏、全文件未遍历块及重复消费会明确失败，停止返回残缺文件。
- 双语表格原有的纯数字、公式只保留一次策略显式登记为已处理；表格译文按行分配路径也登记消费，避免误报。
- 富文本文字与已保存译文不一致时降级输出完整纯文本，并记录句段标识，避免过期或空 HTML 吞掉译文。
- 继续保留内部格式、修订标记残留检查。错误信息不包含客户正文。
